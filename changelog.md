## 2026-11-12
- 014-T1: the geocoding contract is pinned, so the next run has one target. The T1 defect was not a typo — three shapes for `Suggestion` existed at once: `plan.md` said `{id, label, lat, lng, type, attribution}`, the green `contracts/geocode.json` said `{label, coordinates{lat,lng}, attribution, feature_type}`, and the coder wrote `{label, lat, lng, provider, attribution}` against a Mapbox **v5** payload (`formatted`/`center`) where the plan said **v6** (`full_address`/`coordinates`); the token variable was a third mismatch (`MAPBOX_TOKEN` in the plan, `MAPBOX_ACCESS_TOKEN` in the code — a variable that exists nowhere in the repo). `plan.md` now pins the `Suggestion` fields, the token variable, both provider wire formats and the contract↔dataclass mapping; `contracts/geocode.json`, `app/geocoding.py` and `tests/test_geocoding.py` were rewritten to match (12 fixture-only tests, no live calls)
- swarm: a stopped run explains itself in a form you can take away (018). The 014-T1 run spent 50 minutes and 229 calls on a one-line defect, and the operator could not copy the reason out of the dashboard: the "why did this stop?" screen existed only inside the TUI. Every run now writes a plain-text report next to its `run.json` (`<run_dir>/human_log.txt`) naming the stop reason, the reason code, the failing gates, the reviewer's verdict and the changed files; the dashboard screen and the file are the same renderer (they cannot drift) and the screen copies to the clipboard with `c`; `make swarm-log [RUN]` prints it without a TUI
- swarm: the budget panel no longer shows a cap that cannot fire. It read "tokens 1.7M / 2.0M 84.0%" for a run whose dollar and token caps are *not enforced* (`free_local_run: true`), so an operator reasonably concluded the budget had stopped the run — it had not; the run stopped on a failed assertion. A free-local run now shows "no cap: free local run" for tokens and cost
- swarm: a truncated file read names the line to continue from. The read tool caps observations at 3000 characters and said only "re-read with start_line/line_count" — so the 014-T1 coder asked for lines 1–500 of a 178-line file **seven times** and got the same first 85 lines every time, never seeing `search()` at line 169; it spent its rounds re-reading, changed nothing, and the run ended `no_progress`. The note now reads `CONTINUE with start_line=<n> (do not re-read from line <start>)`
- swarm: the reviewer always declares a verdict. It got 9 iterations for 6 gates + `git status` + the verdict + a look at the failing file, so it re-ran `pytest` instead of concluding and `review_verdict` stayed "unknown" — the fix rounds then had no grounded reason to work from. The budget is now 12, and the verdict repair runs on a red run too (it used to run only when the gates were *green*, which is exactly when a verdict is needed least)
- 007-T9: the integration test now drives the *real* walk-mode store. The stuck run wrote its own `frontend/src/lib/navigation/walkMode.ts` — a duplicate of the store that T6–T8 already shipped as `frontend/src/lib/walkMode.ts` — and called `tick()` on the `PositionProvider` interface instead of the `SimulatedProvider` it had in hand. The test now imports the real store, drives it with an injected `SimulatedProvider` (manual ticks), raises the reroute warning on sustained drift, replaces the route on a tapped reroute (`POST /route` stubbed), stops tracking on arrival within 25 m and ends the session on Stop; the duplicate module is gone and `npm run check`/`run lint`/`test` are green
- swarm: the coder checks types and lint before the work is passed on (017). Right after the micro-steps the harness runs the project's *static* checks — the type checker and the linter, never the test suites — and a red check goes back to the coder as a bounded fix round with the same `file:line: message` report QA would have given him. 007-T9 (2026-11-11) spent three QA rounds and two coder rounds on `Property 'tick' does not exist on type 'PositionProvider'`: the checker had named the file, the line and the cause, and one fix round changed no file at all. The commands are configuration (`SWARM_SELF_CHECK_COMMANDS`, or the static subset of `SWARM_GATE_COMMANDS`: `ruff`, `mypy`, `npm run check`, `npm run lint`); `SWARM_SELF_CHECK=0` disables it. The phase is not a gate: its executions are recorded under their own agent role (`harness-selfcheck`), so they are never counted as QA evidence and cannot make a run green. A formatting-only failure is still repaired by the harness's formatter first (`style_failures`), so a wrap never reaches the coder as a code problem. `run.json.self_check` records the commands, their exit codes and the fix rounds. Spec: `specs/017-coder-selfcheck/`

The step and fix prompts also forbid inventing APIs: read the module, use its real exports, add what is missing in scope
- swarm: a style-only gate failure is repaired by the harness, not by a coder round. When the only red gate is a lint/format gate and its output names nothing but formatting (Prettier, or an ESLint rule `eslint --fix` repairs), the flow runs `SWARM_STYLE_FIX_COMMAND` (`npm --prefix frontend run lint:fix`), re-checks the gate and reverts files the formatter touched that the run does not own (`run.json.style_autofix`). A red type check or a red test is never treated as style — that is a code problem for the coder. `SWARM_STYLE_FIX=0` disables it
- swarm: the queue no longer re-runs a task the done ledger already retired. `done_entries()` keyed trailers raw, so legacy commits (`Swarm-Task: 007/T5`, the invocation prefix) never matched the directory name the queue asks for (`007-live-position/T5`) and T5 was re-executed the morning after its green commit — the redo rewrote two files and ended `needs_human`. Keys are now canonicalised through `spec_dir_name()`; "newest entry wins" still holds. Cross-spec advance (`_next_open_spec`) and wrap-around (`_first_open_task`) also honour the ledger and `retry_later` (falling back to a parked task only when nothing else is runnable), and `_resume_point` no longer pins a red run of a task the ledger has retired. 007 T1–T5 are marked `[x]`; T6–T9 were already green on 2026-11-09/10 and are recognised now. T9's green commit (`1f4b3d9`) contained only unrelated Mapbox provider files — `walk.integration.test.ts` never existed — so its brief was re-specified (which reopens T9 alone, per the ledger contract) and the queue resumes there
- swarm: the local-model request timeout is now 30 minutes (`SWARM_OLLAMA_TIMEOUT_SECONDS=1800`, was 300 s). A 9B model at 64k context legitimately ran past five minutes and two runs lost a real generation to `litellm.Timeout: Connection timed out after 300.0 seconds`. The run-level time cap (`SWARM_MAX_RUNTIME_SECONDS`) still bounds the run; cloud calls keep 180 s
- swarm: the local-coder budget exemption now requires $0 spent, not just a local coder. With `SWARM_ALLOW_PAID=1` a paid planner/senior re-enables the cost/token and per-task caps for the rest of the run, and an unknown model price (`None`) is never treated as free. A truly free local run still ignores those caps (the run-level time cap remains) and `run.json budget.free_local_run` records it
- swarm: a stash conflict is now resolved, not just archived (016 AC-8). When `git stash apply` conflicts, a `Stash Conflict Resolver` crew (read + edit only, no shell — it cannot fake gates) re-applies the parked work on the newer tree without duplicating a change that is already there. Accepted only if no marker remains, only the conflicted files were edited, and every gate exits 0; then the stages are cleared, the parked work stays an ordinary unstaged change and the stash is archived with `reason: "resolved"`. Otherwise the attempt is reverted (including out-of-conflict edits), the current worktree is kept and the stash archived with `reason: "conflict"`; `run.json` records `stash_conflict_resolution` (`crew`/`ours`/`kept`) and `stash_conflict_note`. Cleanup/signal paths never call a crew
- swarm: stashes are now a managed lifecycle, not loose landmines (016 follow-up). At kickoff every `swarm-*` stash left by an earlier run is archived as `refs/swarm/archive/<timestamp>-<sha>`, indexed in `swarm/runs/orphan_stashes.json`, then dropped from the stack; a conflicted restore archives the kept stash the same way and records `stash_conflict`/`stash_conflict_ref` in `run.json`. Content stays recoverable with `git show <ref>:<path>` (refs survive GC), the stack never accumulates stale entries a LIFO `stash pop` could apply to the wrong base, and user stashes are never touched. `SWARM_ARCHIVE_STASHES=0` disables
- swarm: an `ollama/…` coder no longer trips the cost/token or per-task caps (its spend is exactly $0); only the run-level time cap remains (`run.json budget.local_coder` records the rule). Three local runs had stopped on the per-task 1800 s clock while still progressing
- swarm: a dedicated merge-conflict crew (016). When `git merge --no-ff` conflicts, one `Merge Conflict Resolver` agent (read + edit tools only, no shell) gets the unmerged files; the harness accepts the merge only if no conflict marker remains and every configured gate exits 0, then commits and pushes it. Otherwise it aborts, leaves the base untouched, and reports `merge_failed` with `autocommit.conflict` evidence. `SWARM_CONFLICT_MODEL` defaults to `SWARM_CODER_MODEL`; `SWARM_CONFLICT_CREW=0` disables. Usage is recorded under role `conflict`. Spec: `specs/016-conflict-recovery/`
- swarm: local work is no longer stopped by a budget. An `ollama/…` coder is exempt from the cost/token and per-task caps (spend is exactly $0); only the run-level time cap (`SWARM_MAX_RUNTIME_SECONDS`) still applies. Three local runs had ended `budget_exhausted` purely on the per-task 1800 s clock while still making progress; `run.json budget.local_coder` now records which rule applied
- swarm: a conflicted stash pop can no longer poison the queue. 014-T8's green run popped its stash onto the base it had just merged, hit a conflict on `frontend/src/App.svelte`, printed `STASH RESTORE FAILED` and left `UU` index stages in the tree; T9, T10 and the next 007-T4 run then gated and edited around conflict markers. Preflight now refuses to start when `git diff --diff-filter=U` is non-empty (`preflight_failed`), and a conflicted restore resolves to `--ours` (the run's or merged work), keeps the stash for recovery, and records `stash_conflict` in `run.json`. 82 runs so far, zero branch-merge conflicts — the merge queue already aborts cleanly, so this was the stash path, not `--no-ff`. Restore now applies the run's own stash commit (`git stash apply <sha>`) instead of a bare `stash pop`: LIFO had already popped a human recovery stash once
- swarm: parked tasks are visible to the queue again. The supervisor keyed `retry_later` from `run.json.spec` (`007/T9`, the invocation prefix) while the flow compared against the directory name (`007-live-position/T9`), so a parked task was retried forever; `save_attempts` also rewrote the file as a flat `{key: count}`, erasing the parked list after one retry. Keys are now canonicalised via `spec_loader.task_key()` on read and write, and attempts + parked list share one schema (`{attempts, retry_later}`), with the legacy flat file still readable
- swarm: the verdict fallback *is* the senior model. `verdict_fallback_llm()` now builds `SWARM_SENIOR_MODEL` (free, tool-capable) instead of a separate `SWARM_VERDICT_FALLBACK_MODEL` id; the env var and `DEFAULT_VERDICT_FALLBACK` are gone. Still free-only: a paid model must never be the reviewer of record
