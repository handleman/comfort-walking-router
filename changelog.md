# Changelog

## 2026-11-10
- swarm: parked tasks are visible to the queue again. The supervisor keyed `retry_later` from `run.json.spec` (`007/T9`, the invocation prefix) while the flow compared against the directory name (`007-live-position/T9`), so a parked task was retried forever; `save_attempts` also rewrote the file as a flat `{key: count}`, erasing the parked list after one retry. Keys are now canonicalised via `spec_loader.task_key()` on read and write, and attempts + parked list share one schema (`{attempts, retry_later}`), with the legacy flat file still readable
- swarm: the verdict fallback *is* the senior model. `verdict_fallback_llm()` now builds `SWARM_SENIOR_MODEL` (free, tool-capable) instead of a separate `SWARM_VERDICT_FALLBACK_MODEL` id; the env var and `DEFAULT_VERDICT_FALLBACK` are gone. Still free-only: a paid model must never be the reviewer of record

## 2026-11-09
- swarm: one configurable local fallback. `SWARM_LOCAL_FALLBACK_MODEL` (default `ollama/swarm-coder:latest`) is now what every role falls back to when its cloud provider is unreachable; `SWARM_<ROLE>_FALLBACK_MODEL` still overrides per role, and the hardcoded `qwen3.5:9b` chains are gone. Fallbacks stay per role, so a coder failure never moves QA
- swarm: the dashboard model list is now per role and live. Live mode reads the effective model each role will call (`llms.role_models()`), `--tail` reads `progress.json` while a run is in flight and `run.json usage.by_role` after it; a role on a fallback is tagged `fallback`, Ollama models `local`. The flow also records `usage.by_role[*].model` and `usage.fallback_roles`, so a paid → local switch is auditable after the run
- swarm: a spent budget no longer masquerades as `reviewer_no_verdict`, and cloud calls get time to finish. 007-T5 spent $0.0624 on five paid steps; the $0.06 per-task cap fired on the QA review, `_kickoff` swallowed `_BudgetExhausted`, and the run parked as `needs_human` with no QA call at all. Budget stops now re-raise and report `budget_exhausted`, the free/local QA review is not budget-gated, the cap is $0.15, and the cloud timeout is 180 s with SDK retries off (the fix generation had been cut off at 2×60 s, six times). AGENTS.md gained a 'harness lessons' section so the next investigation starts from `run.json`/`events.jsonl` rather than the error string
- swarm: scope model fallbacks per role. 007-T4 spent 30 minutes and ended `needs_human` (`reviewer_no_verdict`) because two coder transport timeouts flipped a process-wide switch that moved **QA** to `qwen3.5:9b`; that model looped over the report and never declared a verdict. QA now keeps `ollama/swarm-qa:latest` (a missing verdict already has its own free-model path), the coder falls back to `ollama/swarm-coder` before generic Qwen, and only a provider-wide quota wall switches every role. Also stamped `events.jsonl` rows with `at`, so a stalled call is attributable after the fact
- swarm: correct Zen pricing from the gateway's own `usage.cost` (`glm-5.3-flash` $0.15/M in, $0.50/M out; reasoning billed as output — the old table under-reported ~50%) and treat LLM timeouts as transport faults: 60s request timeout, one same-model retry, then fallback models. Measured calls: 1–7s at 40k prompt tokens, so a timeout is a dead connection rather than a slow generation
- swarm: self-heal installs newly added frontend devDependencies (`npm ls` failure → `npm install`), and cloud calls fail over to the fallback models on connection timeouts instead of spending 5 SDK retries; documented in `swarm/README.md`
- swarm: stop LLM connection timeouts from hanging a run — cloud calls use one SDK retry with a configurable 120s timeout (`SWARM_LLM_TIMEOUT_SECONDS`/`SWARM_LLM_MAX_RETRIES`), a connection/timeout failure immediately switches to the fallback models, and identical failures are never retried twice on the same model
- docs: add `docs/runbooks/overnight-runs.md` (sleep vs lock screen, `make swarm-night`, AC/lid/tmux checklist, supervisor recovery, knobs) and link it from `swarm/README.md`, `AGENTS.md`, and the roadmap
