## 2026-11-14
- 022 T3: timeout economics. `SWARM_LLM_FIX_TIMEOUT_SECONDS` (default 180) applies to fix/self-check/senior/verifier crews while chat-like planner/QA calls keep the 90 s default; a timed-out call is recorded as `llm_timeout` (not a generic failure), retries are counted in `run.json.retries`, and the wall-budget check runs before every retry so a 90 s timeout cannot double the task.
- 022 T2: per-task wall budget. `SWARM_TASK_WALL_BUDGET` (default 900 s, `0` off) is checked between phases and before every retry — never mid-call. On breach the run stops as `needs_human` / `reason_code=wall_budget`, with `run.json.wall_budget_note` and `human_log.txt` naming the phase (`qa: 901s of 900s`), so the record exists instead of the runner timing out. `_WallBudget` is terminal like a budget stop and is never retried.
- 022 T1: phase timing. `events.jsonl` is the only clock: the flow tags crew/agent events with the role set around the kickoff, `swarm/phases.py` pairs `crew_started` with `crew_done`/`crew_failed` (a stack, so nesting is safe), and `run.json.phases` records `{phase, started_at, ended_at, duration_seconds, failed, model}`. `make swarm-report` prints p50/p90 per phase and names the slowest, which is what T2's wall budget and T6's A/B need.
- 022: the lean loop is specced. 021 made the loop correct; the paid bake-off measured the next wall: a two-file task reaches all six gates green in ~5 minutes with `zen/glm-5.3-flash`, then spends 20+ minutes in ~10 sequential phases (planner, steps, self-check, verifier, QA, fix, retry), and the local 9.7B QA hung ~9 minutes on one verdict. `specs/022-lean-loop/` therefore targets latency: per-phase timing derived from `events.jsonl` and reported by `make swarm-report`; a per-task wall budget (`SWARM_TASK_WALL_BUDGET`, default 900 s, stop reason `wall_budget`, never mid-crew); separate fix/verifier timeouts (`SWARM_LLM_FIX_TIMEOUT_SECONDS`, default 180) with `llm_timeout` records and budget-aware retries; opt-in concurrent verifier∥QA (`SWARM_VERIFY_CONCURRENT`, both must pass, locked event writes, sequential fallback); an opt-in lean verifier path for low-risk diffs (`SWARM_VERIFY_LEAN`, docs/tests/mechanical only, implementation paths always verify, `verifier.skipped_reason` recorded — the class-0/1 seed for 024); and a completed outcome-suite baseline with a before/after wall-clock table. Targets: two-file p50 ≤ 10 min, five-case suite ≤ 45 min, green not lower than 021; concurrency and the lean path ship only on a measured win. Control-plane spec, skipped by the queue; 023 is parallel tasks, 024 earned autonomy.

- ADR-012: the orchestration stance is written down, with the event-driven options compared.
