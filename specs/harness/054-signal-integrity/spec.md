# 054 Signal Integrity — Spec

Harness spec (control plane; the queue never runs it).

## Problem

The 2026-11-25/26 session's most expensive failures were not model quality — they
were **false signals** the harness produced or believed. Each is reproducible:

1. **A stale build made e2e lie.** `npx playwright test` (an allowlisted coder
   command) serves `frontend/dist/` via `vite preview` and never rebuilds. During
   the T25 investigation, source instrumentation appeared in no run for ~40
   minutes because the suite was exercising the previous build — and the same gap
   can mark a changed app green on old code. Only `npm run test:e2e` (via
   `swarm.e2e`) builds first.
2. **A false PASS was accepted.** T6:4 ended `review_verdict: pass` with **zero
   recorded e2e executions** while the task required one. The harness now runs
   the suite itself (`1711c5b`), which rescues the run, but the wrong verdict is
   still unmarked — QA is not held to the evidence it claims.
3. **Acceptance oracles were wrong for days.** T19/T20/T21 were fix tasks
   generated by checks that could never pass: `.error` placeholders are always
   rendered (empty), decorative icons have no aria-label, resource 503s from the
   DB-less saved-routes feature were counted as console errors, hidden controls
   counted as zero-size, and the parser missed `- [x] AC-n:` headers (10 specs
   reported 0/0/0). Checks are code with no tests.
4. **Stale acceptance fix tasks re-enter the queue.** T19–T21 kept failing ACs
   that later passed; nothing reconciled them, so the queue would have spent
   paid rounds re-fixing solved problems.
5. **`filter-repo` dropped repo-root hygiene.** The filtered factory history
   tracked **120 `__pycache__` files** because the root `.gitignore` does not
   survive `--subdirectory-filter swarm/`; the same applies to `.dockerignore`
   and LICENSE. Nothing audits the tree before a public push.
6. **A silent UI failure class.** T25: a chained Svelte 4 binding
   (`App → Modal → SearchInput`) stopped propagating with no error and no
   warning; unit tests passed, the verifier (source-only) passed, and only a
   behavioural e2e test could see it. The coder's guess (clearing the input) was
   blocked by the reviewer, but the loop had no oracle to iterate against.
7. **Core and app tests are entangled** (T5b): 816 pass in the factory, 21 encode
   app paths/fixtures/drivers. The factory cannot be green without a split.

## Goal

Make every signal the harness trusts *earned*:

1. e2e evidence always runs on a fresh build.
2. A PASS is rejected when a required evidence command was not run.
3. An acceptance check that cannot pass is itself a failure (oracle self-test).
4. Acceptance-generated fix tasks are reconciled with the current verdict.
5. A pre-push audit rejects caches, secrets and missing hygiene files.
6. A UI bug with an existing failing spec is fixed test-first against that spec.
7. The factory suite has an explicit core/driver split.

## Acceptance criteria

- [ ] **AC-1 (fresh build).** Every path that runs the suite builds first: the
  `test:e2e` script (or the preview webServer) cannot serve a stale `dist/`, and
  the e2e record carries the build time/hash. A test edits a component, runs the
  suite without an explicit build, and sees the change.
- [ ] **AC-2 (evidence-backed PASS).** A reviewer PASS with a required e2e (or
  gate) execution missing is recorded as `review_unsupported` (or re-asked once),
  never green. The judge record names the missing command.
- [ ] **AC-3 (oracle self-test).** `make swarm-accept --selftest` proves each
  declared check can pass (on the current build) and fails when its selector is
  mutated; a spec with criteria but no checks is a configuration error, not a
  silent 0/0/0.
- [ ] **AC-4 (reconcile fix tasks).** Before a task tagged `acceptance` runs, its
  AC is re-evaluated; a now-passing AC closes the task with the verdict instead of
  spending a round.
- [ ] **AC-5 (factory audit).** `make factory-audit` (or the 048 checklist) fails
  on tracked caches/binaries, a missing `.gitignore`/`.dockerignore`/LICENSE, a
  `.env`, or a blob > 1 MB, and runs before any push.
- [ ] **AC-6 (test-first UI).** When a task's failing evidence is a named spec,
  the fix crew receives that spec (or its failure tail) as the oracle and its
  success is that spec passing at the current delta.
- [ ] **AC-7 (core/driver split).** Factory tests are marked core vs driver;
  `pytest -m "not driver"` is green with no app tree, and driver tests skip with
  a named reason.
