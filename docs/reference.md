# Commands & boundaries

Verified command list and the repo's entrypoints / boundaries. See [GLOSSARY.md](../GLOSSARY.md) for terms.

## Commands (verified 2026-11-08)
- One command dev: `make dev` — bootstraps `.venv` + `frontend/node_modules` on first run, then backend `:8000` + frontend `:5173`; Ctrl-C stops both.
- Install only: `make dev-setup` (Python 3.12 `.venv` from `requirements.txt` + `requirements-dev.txt`, then `npm install` in `frontend/`).
- Run one side: `make dev-backend` (`http://localhost:8000/docs`), `make dev-frontend` (`http://localhost:5173`).
- App tests: `make test` (`pytest`, scoped to `tests/`). Single test: `.venv/bin/python -m pytest tests/test_route_api.py::test_route_matches_contract -v`.
- Harness tests: `make swarm-test` (uses `swarm/.venv`).
- Lint: `make lint` (`ruff check .`). Types: `make typecheck` (`mypy app tests`).
- Frontend: `cd frontend && npm run check` (svelte-check), `npm run lint` (ESLint + Prettier check), `npm run format`, `npm run build`, `npm run dev`.
- Swarm: `make swarm-run|swarm-local|swarm-dash|swarm-up|swarm-up-local|swarm-test|swarm-stop|swarm-approve|swarm-preflight|swarm-sandbox`.
- Spec acceptance pass (043): `make swarm-accept` — the final greenlight. Picks every `specs/product/*` spec with a ticked task, serves the local build (`vite preview` + fixture backend), checks each AC in a real browser at desktop + mobile (deterministic probes `exists`/`absent`/`count`/`min_count`/`text`/`value_set`/`route_request`, plus global facts: console errors, map tiles, duplicate buttons, zero-size inputs, overflow), adds a free vision-model second opinion, writes `<spec>/acceptance.md`, appends one unchecked `T<n>` fix task per failing AC (deduped), and exits non-zero on FAIL. Runs in two places: after every green feature task inside the swarm flow (`swarm/flow.py` calls the pass on that task's spec; verdict + queued fix tasks land in `run.json.acceptance`), and when the queue drains via the supervisor (`make swarm-accept`). Off switches: `SWARM_ACCEPT=0` (disable the hook), `SWARM_ACCEPT_VISION=0` (skip vision), `SWARM_ACCEPT_QUEUE=0` (report only). Per-spec checks live in `specs/product/<spec>/acceptance.toml`; a spec without one still gets the global checks + vision + a report. Additional off switches: `SWARM_SKILLS=0` (disable skill injection), `SWARM_SKILLS_DIR=<path>` (point to custom skill folder).
- Local Postgres (005): colima is part of the swarm lifecycle — `make swarm-run|swarm-up|swarm-local|swarm-up-local` start it best-effort (`swarm/db.sh up`, idempotent), and `make swarm-stop` and `make swarm-db-down` both stop colima *and* the pilot. `make swarm-db-up|down|status|migrate` still work standalone (`make test`/`e2e` read `DATABASE_URL` if it is up). Missing colima is a no-op (DB-gated tests skip); preflight prints its status.
- Browser suite: `make e2e` (builds the frontend, boots the fixture backend via `frontend/playwright.config.ts`, runs `playwright test`); it is the evidence 026 requires for a task naming `frontend/e2e/*`. Manual completion of a task: `make swarm-record SPEC=014 TASK=T11` writes the standard green trailers as an empty commit (`--dry-run`/`--no-commit` available).
- Swarm economics/autonomy (015): `make swarm-supervise` (unattended queue, retry/backoff, `retry_later`) and `make swarm-report` (cost per green task, tokens per role, fix rate, stops). Per-task caps: `SWARM_MAX_COST_PER_TASK`/`SWARM_MAX_SECONDS_PER_TASK`; routing: `SWARM_LOCAL_FIRST`, `SWARM_PAID_ALWAYS`; hygiene: `SWARM_SELF_HEAL`, `SWARM_STASH_UNRELATED`, `SWARM_REVERT_OUT_OF_SCOPE`.
- Unattended/overnight: `make swarm-night` (`caffeinate -is` + supervisor). A locked screen is fine; system sleep is not — runbook: `docs/runbooks/overnight-runs.md`.
- Approval hold: `./swarm/run.sh 001 T3 --require-approval` (or `SWARM_REQUIRE_APPROVAL=1`); release with `make swarm-approve` (defaults to the last checkpoint task; `SPEC=001 TASK=T3` to be explicit) or the dashboard `a` key.

## Boundaries / entrypoints
- `app/` + `tests/` → root `.venv` (app deps only). `swarm/` → `swarm/.venv` (CrewAI). `frontend/` → npm. Do not mix them.
- Backend entrypoint: `app/main.py` (`app = FastAPI(...)`). `app/router.py` was removed; do not reintroduce a second app/route mount.
- API contract: `contracts/route.json` is the source of truth (ADR-005): `POST /route`, preference enum `hot`/`cloudy`, GeoJSON `geometry`, `{ code, message }` errors.
- Dark-factory Phase 2 (`specs/013-dark-factory-phase-2/`, done): done ledger from commit trailers (`Swarm-Task`/`Task-Hash`/`Spec-Hash`, so green-but-unchecked tasks are skipped and spec/plan edits reopen them), approval-resume commit of a held run's verified delta via the merge queue, and atomic per-step `progress.json` crash checkpoints (plan/file/age validated; gates+reviewer always rerun).
- Harness efficiency (020, `specs/020-harness-efficiency/`): `make swarm-bench` scores a frozen 12-case corpus with **no model call** — per case it builds the real crews and report and counts prompt chars, report chars and gates/round (baseline `swarm/bench/baseline.json`). Prompts come from `swarm/prompts.py` with a byte-stable per-task prefix (`prompt_prefix` hash recorded per case); full step outputs go to `<run>/step_outputs/` and long gate tails to `<run>/gate_logs/` (`SWARM_CONTEXT_COMPACT`), the inner loop runs only the affected gates with the full suite before green (`SWARM_GATE_SELECT`, `SWARM_GATE_MAP`), reports carry key lines once, coder crews get `Repo Search`, and `make swarm-bench-live CASE=<id>` replays one case in a throwaway worktree. Measured vs baseline: task prompt −6.6%, report −86%, inner-loop gates −40%. The −30% prompt-char target is recorded as missed (per-step agent/tool overhead dominates), not claimed. Control-plane spec, skipped by the queue.
- **Replay suite now completes** (2026-11-15, OpenCode Go): `make swarm-replay --timeout 900` finished 5 cases in 13 minutes with **1/5 green** — `004-T2` green (202 s, 1 fix round), `005-T2` and `006-T3` `correction_reverted`, `007-T2` `delta_incomplete`, `010-T5` timed out. The 021/022 targets are therefore still not met, but the failure is now typed and fast: the correction guard (026 AC-4) ends a case before QA can judge it, which is the next thing to A/B for the replay path.
- Fix loop (021, `specs/021-fix-loop/`, implemented): the measured waste after 020 is the second round (59% of green runs, 44.6% of prompt tokens, 3× wall clock). It now has an outcome replay suite (`make swarm-replay`, `--off` A/B), per-round `fix_cause` telemetry, deterministic repair before QA, a tests-first A/B (`SWARM_TESTS_FIRST`), an AC-aware coder prompt A/B (`SWARM_CODER_ACS`), `SWARM_CODER_LOOSE`/`SWARM_PLAN_MAX_STEPS` A/Bs, repair-budget/checkpoint policy (`SWARM_MAX_FIX_ROUNDS`, `best_delta`), verification ROI (`self_check.hit`, `verifier.hit`), verifier stability (`overridden`/`stalled`/`unstable`) and a step-landing check. **Measurement is incomplete**: the baseline run produced `005` `verifier_blocked` (747 s), timed out on `004`/`006` at 2400 s, and never reached `007`/`010`, so `swarm/bench/replay_baseline.json` is `complete: false` and the AC-9 targets are recorded as not evaluated. The harness correctness fixes are validated (the verifier now passes after a correction and QA is reached); the loop still does not converge on these cases, so the next step is a model bake-off and a faster case set. Investigation: `docs/research/fix-loop-2026.md`. Control-plane spec, skipped by the queue.
- Lean loop (022, `specs/022-lean-loop/`, implemented, measurement partial): phase timing from events (monotonic stamps; roles resolved by crew object because CrewAI emits from its own thread), a per-task wall budget (`SWARM_TASK_WALL_BUDGET`, stop reason `wall_budget`, checked between phases and before retries, with each agent capped at the remaining budget), separate fix/verifier timeouts (`SWARM_LLM_FIX_TIMEOUT_SECONDS`) with `llm_timeout` records and `run.json.retries`, opt-in concurrent verifier∥QA (`SWARM_VERIFY_CONCURRENT`), an opt-in docs-only lean verifier path (`SWARM_VERIFY_LEAN`, the class-0/1 seed), and a `last_phase` record when the runner kills a case. Measured: the budget stops a case with a `run.json` instead of an anonymous timeout; **the first live green exists** — `004-weather-sun-T2` at 433 s, 176k tokens (78k cached), $0.0414, one fix round (`replay_baseline.json`, `complete: false`); `004-T3` was also green (315.6 s, $0.029) in the same worktree. The five-case suite and the AC-6 wall-clock target are still not measured; concurrency and the lean path stay off until an A/B wins. Budget defaults are 1800 s wall, $1.00/cost and 2400 s per task. Control-plane spec, skipped by the queue.
- Parallel factory (023, phase 1, implemented): `make swarm-parallel BATCH="spec:task,..."` runs independent tasks in detached worktrees with the current harness (`--no-commit`), takes up to `SWARM_WORKERS` from a group whose briefs name disjoint files, and integrates only greens **serially**: `git apply --check` → apply → full gates on the main tree → commit with the standard trailers → best-effort push. A conflict or failed gate reverses the patch and leaves the task open; the main tree has one writer. Live throughput is **not measured** yet (no green baseline). Control-plane spec, skipped by the queue.
- Risk labels (024): `swarm/risk.py` labels a run 0 docs / 1 tests / 2 logic (`app/`, `frontend/src/`, `contracts/`) / 3 control (`swarm/`, `specs/`, migrations, auth/payments/infra, config, unknown); a sensitive brief forces 3, an empty delta is 3. The label is **telemetry, not a gate** (the autonomy knobs were removed on 2026-11-15): it lands in `run.json.risk` and feeds the escape rate. `swarm/docs/risk-classes.md`. Control-plane spec, skipped by the queue.
- Self-healing e2e (027, `specs/027-e2e-self-heal/`, implemented except the bench case): when the recorded suite is red the harness triages it deterministically (`env`/`flaky`/`coverage`/`impl`/`drift`), writes a repair roster (`<run>/inner/{spec,plan,tasks}.md`, queue format, `frontend/e2e/` only), runs it through the fix crew, re-runs the suite through QA and re-triages — bounded by `SWARM_MAX_INNER_TASKS` (3) and `SWARM_MAX_INNER_ROUNDS` (2). `swarm/e2e_guard.py` refuses a repair that deletes a test, adds `skip`/`fixme`/`only` or drops an assertion, reverting it as `e2e_weakened`; `env` and `flaky` stop without editing anything, `impl` stays with the code fix loop. `run.json.e2e_self_heal` records it; `SWARM_E2E_SELF_HEAL=0` disables. Docs: `swarm/docs/e2e-self-heal.md`.
- Durable journal (025, ADR-012 option C first slice, implemented): `swarm/journal.py` is a SQLite/WAL append-only journal with idempotent `(run, key)` events, step status/attempt/**leases** (atomic claim, owner-only heartbeat, TTL), an **effects** table (`commit:<run>:<delta>` makes a retried commit a no-op) and `fold(run)` as the projection in `run.json.journal`. The flow writes `run_started`, seeds/completes steps, resumes from the journal's contiguous completed prefix when it is longer than `progress.json` (recovery note `journal`), and records the commit effect. `run.json`, `events.jsonl` and `progress.json` remain the operator views; green is still QA's evidence. No dispatcher/workers/Postgres yet — those are the ADR triggers. Control-plane spec, skipped by the queue.
- Escape rate (024): `make swarm-report` joins every merged (green) run with git (`This reverts commit <sha>`) and reports escapes per class. It is a floor (a hand-fixed regression is not counted) and the only signal that would justify reintroducing a ceiling.
- **The swarm is autonomous; there is no autonomy setting** (2026-11-15, `specs/024-earned-autonomy/`): a green run whose gates are all `0`, whose reviewer says `PASS` and whose verifier is not blocked merges by itself in every risk class. `run.json.risk` still labels each run (0 docs, 1 tests, 2 logic, 3 control) and `make swarm-report` turns reverts into an escape rate per class — telemetry, never a gate. The only hold is the explicit per-run `--require-approval` flag (`awaiting_approval` → `make swarm-approve`); nothing in `.env` can make the loop stop merging.
- Run guards (026, `specs/026-run-guards/`, implemented): the 2026-11-14 failures are now
  typed, deterministic stops. A **delta guard** stops an empty in-scope delta (`no_delta`) or
  a brief-named file never created (`delta_incomplete`) **before** the self-check/verifier/QA
  (`run.json.delta_guard`, `SWARM_DELTA_GUARD=0` off); **judges fail closed** — verifier, QA
  and senior go through `guards.resolve_verdict` (parse → **one** repair call → terminal stop,
  `run.json.judges`, `SWARM_JUDGE_FAIL_CLOSED=0` off), because 014-T10 committed green on an
  `unknown`; a **correction cannot regress the build** — the 017 static checks run before a
  correction plan and after each step, a green→red transition reverts that step's paths
  (`<run>/reverted/`) and ends the loop as `correction_reverted` (`SWARM_CORRECTION_GUARD=0`
  off); **quota is terminal** — counted per provider, stop `quota_exhausted` at
  `SWARM_QUOTA_LIMIT` (3), fallbacks skip providers with no key, preflight makes one 1-token
  call per role (`SWARM_QUOTA_BREAKER=0` off); **cost is never silently unknown** (two paid
  models price per model, an unpriced one sets `usage.cost_unknown` + names it);
  **e2e evidence** — a brief naming `frontend/e2e/*` is green only with a recorded Playwright
  run (`reason_code=e2e_missing`, `make e2e`, `SWARM_E2E_EVIDENCE=0` off); **config errors are
  readable** (`run.json.error` + `human_log.txt`, preflight builds the crews' own factories);
  **one retry authority** (`max_retry_limit=0` on every agent, now shared via the internal
  `_senior_agent(task, kind)` / `_conflict_resolver_agent(kind)` factories in `swarm/crew.py`,
  which consolidate the two duplicated pairs into one shared constructor); and **the queue
  explains itself** (`run.json.queue_reasons`, `open task <spec>/<T>: <reason>`, `make swarm-record
  SPEC=… TASK=…` for a manual completion). The **wall budget is terminal**
  (`run_bounded(None)` is the only unbounded mode, a spent budget refuses the call and raises
  `_WallBudget`), and `append`/`record_effect` no-op after the journal closes.
- Swarm queue: the harness reads only unchecked `- [ ] T<n> (AC-…): brief` lines from `specs/product/*/tasks.md`, in directory order; authoring rules + scope/`--replan` notes are in `swarm/README.md` ("Adding a spec to the swarm todo list"). Harness specs (`009`, `012`–`033`) live in `specs/harness/` and are always skipped (the list is `HARNESS_SPECS` in `swarm/flow.py`, a backstop to the folder). The swarm does not edit spec files — mark `[x]` yourself after green (or rely on the 013 done ledger). Non-green statuses: `needs_human`, `awaiting_approval`, `commit_failed`, `push_failed`, `merge_failed`, `crew_error`, `quota_exhausted`, `budget_exhausted`, `interrupted`, `preflight_failed`, `lock_stale`, `checkpoint_stale`, `phase_timeout`, `lock_held`.
- Do not invent commands or config. Verify via manifests/scripts before claiming a workflow exists.
